# FASE 6.3B-L1-F3AQ - F3AO harness environment loading fix

F3AQ preserved F3AP and all prior history. The F3AO result was caused by
launching the experimental harness without loading `.env.e2e` before the
coordinator module/gates were evaluated. The runtime classifier itself was
not changed.

The minimal harness-only fix adds synchronous `process.loadEnvFile('.env.e2e')`
before the dynamic coordinator import in
`scripts/e2e/test-flow-l1-f3ao-normalized-inspector.mjs`. This makes the local
environment available before `checkProjectIsolation()` without editing any
`.env` file, hardcoding values, or executing the coordinator.

`NEXT_PUBLIC_SUPABASE_URL` and `E2E_EXPECTED_PROJECT_REF` were verified as
present without printing their values. `NORMAL_SUPABASE_PROJECT_REF` is an
optional exclusion input in the existing predicate and remained absent.
